## 2. 扫描方法（一次性 PIL 脚本，未落盘于工程内）

沿用 `docs/1png-control-buttons.md` 的方法并只针对"图标簇"收窄：

1. **顶栏 ROI**：限定 `y=[10..55]`（理论工具条带）。对每个像素做灰度 `mean(RGB)`，
   **暗阈值 `<120` = 前景**（图面工具条底色实测近 `#F8FCFC`，暗线约 `#181818/~#2E3030`）。
2. **横向分簇**：把命中暗色像素的列按"连续、最大空隙 ≤6px"成簇，得到列 span（`gap=6`）。
   顶栏得 6 簇，列 span 如下章 §3。
3. **簇内求 bbox + 行/列 run 长度**估计描线粗细（水平 run median≈2，实际实心 1.5~2px）。
4. **语义判定**：把每簇全分辨率 1:1 ASCII 化（`#`前景 `.`背景），再 NEAREST 放大 10× 目视锚定。
5. **彩色探测**：`饱和 = max(RGB)−min(RGB)>40` 抓蓝/红实心部分（本图顶栏仪表图标几乎全单色，
   只有"logo 钮"带实心蓝）。见 §3、§6。

> 结论锚点：这幅图的**大部分区域是日志文本 + 下拉**，真正的"图标"集中在**顶栏一横排 6 个**
> + 右缘 1 个齿轮。工具栏区在多次独立扫描（本簇扫描 vs 前文档色板扫描）给出同一 y 带与 x 间距，
> 坐标可信。

## 6. 复选框（V 勾号）实测

在整个可点击表单扫描「小尺寸(~ ≤16px)暗像素」：
- **未发现** canvas 大面积、独立圆角的 `□ + 对勾`。
- 勾号出现的形态多为**图表/列表结构里右缘的 ”✓“叠加在暗底**，即**行内全字对勾**而非独立复选钮。
- 实际最接近复选的图形位于 **grid／参数表格的"启用列"位置**（`x≈204..216,y≈124..149`，
  一个窄结构呈 **阶梯折返**，中心竖影带），判断为**"使用循环发送/开区间"多折选区指示**，
  不是标准 V 勾。
- 结论：**1.png 没有可用基准复选方框勾形**。若 bridge 未来做 checkbox，参考
  ImGui `Checkbox` 的默认框即可，本图无从对齐。

> 结论可靠度：本图多复用「下拉」（§7），却很少出现勾选框，与所见表单一致。

## 7. 下拉箭头（combo 右侧小三角）

在暗色前景簇里捕获两组确定的**下拉细三角**（真实几何）：

### 7.1 combo 下拉箭头（第 2 组，配置内）
- 出现于发送工具栏下方层级，`y≈82..100` 一带：
  - 三角实体底 ~12×12，位置 (x=215..228, y=83..94)，由**上分两聚再到下收敛**：
    `…###…` 顶两连 ->中间 → 底部 `..####..`，全部**实心三角**（下边长大、顶小），均匀灰度。
  - 实质是一个**向下开的封闭小三角（宽 12、高 11）**。填充是前景统一暗色（r 处反锯齿）。
- 组 2 的同类信号在 (x=369..379, y=86..91) 也出现**更小 `⌄`（宽 10、高 5 双翼）** ——
  为另一字段的小三角;多为同级控件。

### 7.2 纯红向下箭头（x≈688–706, y≈122–142）

不是 combo 内置灰箭头，是**深红实心、向下渐窄的三角指针**（近全 1px 反锯齿，纯饱料红）。用
`R`=红、`+`=过渡 打印在该面：
```
     R              ← 顶上尖收
    +RR+
     +RR+
       RRR           渐宽
        RRR → 向下扩散
         RRR
 RRR     RRR         (底部左外围另有相邻红字 R 段,非本箭头)
 RRR     RRR
        RRR
       RRR          ← 再收底成一点
     +RR+
    +RR+
     R
```
- 结构：**顶窄点 → 中腰最宽 → 底又收窄**的"腰鼓/压扁菱形"向下指针（如工具栏”下移/更多“标识）。
- 行 x≈685..688(y≈134..137) 的 `RRR` 是一个红色**相邻文字笔画**，非箭头本身（避免误判）。
- 这是全图**唯一大面积纯红饱和块**，比 §7.1 的灰 combo 三角要醒目得多。

综合：1.png 的下拉/箭头形态有两种——**灰 combo 微三角**（§7.1, 8~10px）与**红实心向下腰鼓指针**
（§7.2, ~18×20）。build 内若要 micro-arrow，可按 §7.1 的灰三角为准，draw 不必 1:1 红。

## 9. 建议（供参考，未实施）

### 9.1 线帽 / 圆角 —— 与本工程 ImGui 实际 API 的匹配（重要约束）
- **实测结论**：1.png 的工具图标全是**反锯齿字体轮廓 glyph**（图标2圆环边与图标5笑脸大圆环
  反锯齿 ≥2px 过渡 ⇒ 圆滑非 90° 直角；图标3 折线末端多收成锐点）。等效视觉是**微圆头细线 + 细弧**，
  不是硬 butt 的方角线。
- **本工程 API 事实（编译级，非建议）**：项目实际 ImGui 头
  `third_party/xcom_imgui/imgui/imgui.h`：
  - `AddLine(p1,p2,col,thickness)` —— **只有厚度参数，无 cap flag**（行 3507）。
  - 该头里的 `ImDrawFlags_`（行 3417‑3427 区）指**矩形圆弧 `RoundCorners*`**（配 `AddRect`/填充高圆角），
    **不存在 `ImDrawFlags_RoundCap`**、不存在线帽 flag。so 之前"给 AddLine 第 6 参 `RoundCap`"的说法
    **在该仓库无法编译**（Do NOT 这样写）。
- 故若想让线端圆滑，只两条正统路径：
  1. **保持现状 butt**（默认）：Clear 的 X、Path 顶部折等"尖/直"图形完全够用（对齐 1.png 图标2/3 尖锐处）。
  2. **对要圆头的弧**：在每个端点补一颗 `AddCircleFilled(endpoint, r=thickness/2)` 即线段帽——
     例如笑脸眼/嘴弧若现加（bridge.cpp:520 附近目前无此型，若新增再说），或 Refresh 的圆本来无帽问题。
- 影响范围集中在 bridge.cpp:501‑515（IconButton 手绘图标）与 520‑550（WindowButton）。
  现有四 UtilityIcon 多用直线，**现状 butt 已够**，不需为 1.png 改全局；线宽 1.6~1.8px 亦可保留。

### 9.2 是否迁移图标字体
- 现 cursor 表（IconButton）横竖简单可用但**几何是直角 X / 矩形 / 圆** —— 截图图标是
  曲线/Fluent glyph，用手写线很难 1:1。但用户说明不换字体，故：
  **维持 DrawList 手绘，不建议现在引入 codicons.ttf**。
- 若未来做，参考 ImHex codicons.ttf 的路由即可，此处不强推。

### 9.3 逐 UtilityIcon 的重画细节建议（坐标/口径，基于 1px≈0.0573,不引入字体）
给“想重画 1.png 那几个图标到 bridge”的最小改动路径，全部数字为中心 28×26 `kSize`：
- 图标2（圆角“图表/面板”框）：与 bridge Save 的直角 Rect 不同，需圆角。可用
  `AddRect(center±(r), …, rounding≈3px)` 改圆角框 + 内部两条小折（近似外框内页），不必新引擎。
- 图标3（波形‑收拢 / 双列支架）：最适合现状 bridge，可用两套 `AddLine/AddPolyline` 复刻
  底部横基线 + 左竖双锋；沿用 IconButton 的 center 算法（bridge.cpp:499‑500）。
- 图标4（`?` 问号/Help）：现有 UtilityIcon 无此形。最小成本 = 直接 `ImGui::TextColored` 打"?"字符
  再局部描重，或 `AddPath` 手绘圆钩+竖+点（成本高于另两枚）。
- 图标5（笑脸）：现有 Refresh(圆+三角) 完全不像。若要，手绘 = `AddCircle(r≈12)` 轮廓 +
  上两小眼(短横圆 cap) + 下内弧嘴，线宽对齐 1.8px。
- 齿轮 SETTINGS（bridge.cpp:520+ WindowButton 已有 kind.Minimize/Maximize/Close；若要仿 4.6 的"设置"
  可在旁新增 kind={Settings}：`AddCircleFilled`/外齿用多圆叠底，再 `AddLine` 画 4~8 根辐条）
- 建议**统一表观线宽**、圆 cap 开关放常量。因顶栏并非接收/日志核心热路，改图标不伤主渲染 perf。

> 免责：以上重画路径是**给人类工程师的决定参考，未改动任何文件**。截图缺 hover/pressed 态与
> 焦点状态，圆角/填充还原度靠静态盘面推断存在误差。
