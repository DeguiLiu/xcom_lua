# 1.png 发送区（Transmit / Send）像素级规格研究

> 纯只读研究文档：对 `pic/1.png`（**1802×1291** RGB，SSCOM 系浅色参考界面）做 PIL 逐像素扫描 + Tesseract
> (chi_sim) 定位文字，抠「发送/发送设置/发送参数」整块的**真实几何、坐标、尺寸、配色**，
> 并与 `xcom_imgui_bridge.cpp` 现有 `TransmitContent / SendAction` 逐点对照，指出待改项。
> **本环境 Read 无法目视 PNG**（截图脚本无法直接读图），故全部采用像素+OCR，含糊处如实标注。
> 坐标均为 1.png 实际像素（x=0..1801, y=0..1290）。日期 2026-09-05。
> 方法与前三份一致：`1png-control-buttons.md / 1png-input-select.md / 1png-icons.md`。

## 0. 结论速览（先读）

1.png 是一张**极稀疏静态版式/配色参考**：可点击内容几乎全在**左列（x≈0..侧栏宽）+ 顶栏**；
右侧 (x>一个界面留白) 到中下部**整片纯白不收/空面**，**不存在经典串口「底部发送编写坞」**——
即**没有**多行发送编辑器 Tab、Single/Multi 槽、`分页 1/3 ▷`、`1/2/3…槽 + Send N`、
`+/-` 页、实色大 SEND、Loop ✔。本报告如实列出所有「找不到」。

真正与“发送/收发”有关、且能在 1.png 上**测到像素**的，其实只有三样：
1. **左列一张单行「周期/自动」参数组**（间隔数字框 + 单位，见 §3）——对应 bridge 的
   `##send_period InputInt(ms)`（bridge:1212）、循环周期。
2. **一个 send-arrow / 发送字形钮**（右下，x≈1672..1727, y≈1159..1197）——但那是**深色线描字形**
   浮在空面上，非现在 bridge 的实色 SEND 大钮（对比 A 文档 SendAction 结论）。
3. **左列几条「收/发设置」级联开关 & 带值下拉**（§4），含 HEX/进制方向设定相关选项。

即：**“本地可发能力控件（编辑器/分页/LOOP/HEX/页签/实色发送钮）”在 1.png 全未落图**，
现运行中的 `TransmitContent` 坞（bridge:1192 及其下方 send_workspace 分区）是自 920×650 真机
动态产物，不在本参考静态帧里（1.png 空面 y≈1120..1160 等整空白就是证据）。→ 待改项的入口是
「把 1.png 左列可见的间隔/开关型参数校准后映射到 TransmitContent」，而不是去 1.png 找副坞。

## 3. 发送相关“数字间隔/周期”参数（最重要引擎对象，可 1:1 对齐 ms/秒）

两处都是**短 InputInt + 右侧单位 + 尾部问号/提示**，同列排布考究——最贴近 bridge 的 `##send_period(ms)`
与 Multi `##multi_period(ms)`：

### 3.1 `定时发送`/自动断帧 周期数值框（y≈524..554）
- 整行前缀框 `(|` 于 x≈9..39；label(中文) x≈53..134（断帧行）或 x≈58..134（定时发送行）。
- 数位文本 bbox（Tesseract word）：
  - 断帧行：`20` 于 **x≈274..295, y≈533..548**（居中偏上）, 单位 `ms` 于 **x≈321..344, y≈536..546**，
    `?` 于 **x≈376..386, y≈530..545**。
- 定时发送行：`1.0` 于 **x≈275..299, y≈837..852**, 单位 `秒` 于 **x≈372..391, y≈837..857**。
- 内里为白底 #FFFFFF + #D5D5D5(1px)框的浅槽（B/input 文档 frame 同源）；数位值列锚 x≈274-345，
  恰与参数字段“值列右区”同一锚，说明它在 tabular 对齐上同 COMB field。

→ 待改：bridge 两个周期 InputInt（bridge:1212 width 80px 的 `ms`、bridge:1316 is 80px）几何上已接近；
  1.png 单位是**ms / 秒**两套且 `定时发送` 单位明确是“秒”，若想贴近应在该处把步进/后缀也区分。

### 3.2 与其相望的“Loop/循环”概念
在 1.png 数值行文本中，前缀 `(|/(|)）` 即为“周期使能”的圆角开关（B 文档 33px 墩式）。1.png 里
**未画出** `Loop`/`AUTO` 英文字作为独立 toggle label——这两词以及 bridge 用的 `AUTO`(1207) 都是
现跑坞英文名称（TransmitContent 自造），与 1.png 的“自动…/定时发送…”行字面不是同一命名，故不能
要求 1.png 提供 Loop 字样做基准；语义等效即可。

### 5.1 send-arrow 字形（右下，唯一像“发送钮”而其实是**深色线描字形**在空面上）

- 语义与“发送方向发送”一致 → 若要给运行中“SendAction”大钮做**1.png 同风**的轻量替换，
  既不是现在实底 kSendBlue(0x005A98 全填充, bridge:328/1498 rounded 8)，也不是图标；1.png 更接近
  白底+深字形 icon。但注意现有 UI 已在按钮 doc 建议里把 Send 保留实用钮——这里只记参考外形。

### 5.2 全宽蓝高亮带（不是发送钮）
- 于 **x≈425..1797, y≈1097..1099（3px）**，采样 (426,1098)=(38,114,172)≈#2672AC 蓝（与主蓝一系）。

## 8. 脚本与方法备注
