## 2. 分隔线 / hairline —— 实测与 bridge 逐点对照

### 2.1 先钉全幅"三列"骨格（容器的天然分隔，也是唯一 2px #EDEDED 的宿主）

横向逐行"非浅色规则扫描"干净结果（只保留 ≥300px 的横贯灰线）请对照下表；同时竖向列扫描抓直分隔：

| 区 | 实测 | 出处 |
|---|---|---|
| **工具横条** y≈0–59 | 底色渐白 `#FAFDFE..#FCFDFD`，图标中线 y≈29（见 icons doc） | 逐行 0–59 |
| **主界满分隔线 y=60 与 y=61** | **两行都是 `#EDEDED`，run=1802，x=0..1801**（顶部连续 2px） | 逐行 |
| y=62 起主区内容 | 紧接 `#FEFEFE`/白，无其它全宽横线 | 逐行 |
| **左参数列** x≈8..398，纵向卡片 | 见 §3.1 | — |
| **中间竖直 light-rule** | **x=423–424 列几乎整高（y60..1260，>1100px）为同色浅灰带**（§2.3） | 列扫 |
| **右日志列** x≈426..1802 | `#FEFEFE`/`#FFFFFF` 内容底，x1797-1798 有 `#E4E4E5` 竖细带（§2.4） | 列扫 |
| **页脚 status 行** y≈1254（右） | 见 §4 | — |

**结论 D1a——用户记录的"#EDEDED 2px"真实存在，但特指主 1 条 2 层高**（y60、61 两层都满带宽），
它不是"两条 1px 分色线"，而是一条 2px 厚的 #EDEDED rule。bridge 里 `kRule=0xEDEDED`(:326) 本记为
"1px hairline"，**建议把厚度概念取 2px 或画 1.8~2px**，否则视觉会细于 1.png。

### 2.2 三条左列内部横分隔（较深的 #DEDEDE，非 #EDEDED）

| y | 主色 | x 范围 | run | 解读 |
|---|---|---|---|---|
| 390/391 | `#D5D5D5` | x≈12..399 | 388 | 左列某子卡片顶边/控件 frame （边框层） |
| 398/399 | `#DEDEDE` | x≈9..402 | 394 | 左列一张"卡片"顶上沿 |
| 659/660 | `#DEDEDE` | x≈9..402 | 394 | 同上，向下第 2 张卡片分界 |
| 872/873 | `#DEDEDE` | x≈9..402 | 394 | 第 3 张卡片分界（y 节奏 ~=(659−399)=260px, (872−660)=212px，非等距） |

> 这三条 #DEDEDE 全长等于"左参数列卡片组的横向跨段"，说明左列是**上下叠放的多张浅卡片**，
> 每张以一条 DEDEDE 顶边线分界 (border-top style)，**不是**整列单一大面板；且 x=9..402 ≈ 左列宽，
> 到 §2.3 那条中间 light-rule（x423）为止即整列卡片群宽度，规则一致。

### 2.3 中间竖直分隔（左参数列 ↔ 右日志列）—— measurement 入细

列扫 x=400..434（限 y60..1260 的灰值计数）：

| x | 灰灰度命中 | 说明 |
|---|---|---|
| 401–402 | 500–563 | 邻近左列卡片右缘界面（部分底为 #FBFBFB/灰过渡） |
| 403–422 | ~2（几乎为零） | **空沟：底色回到窗口白/主题 (#FEFEFE)**，即左右两列并不贴边 |
| **423–424** | **1166 / 1176**（整高） | **竖直 1px≈2 列浅灰 rule（色 ~#EF/ED 类）** = 右日志列真正左边缘 |
| 425–… | 小 | 右日志列内容底 #FEFEFE 开始 |

即：**宽沟 ~20px 的全空（无画线）+ x423 一道几乎全程的浅灰竖 line**，把左卡片群 与 右日志 分开。
bridge 的 `col_gap` 实现正是："透明空沟 child 宽 `gap=6px`，在其中点 `AddLine` 一条 `kRule=#EDEDED`
1px 竖线"(:2388–2407)。**对照**：bridge 空沟 gap=6px / 竖线 #EDEDED 1px；1.png 的空沟 ~20px、竖线在
x423 更贴近每条日志的列边（不是中线式的沟中带），且竖线颜色更近 #EF 而非纯 ED。建议「把 gap 加宽、
竖线靠列边 1px、色可留 #EDEDED 即可」。（bridge 注释口述 1.png 为"#E6E6E6"——实测更偏 **#EF/#ED**，
见 §6 勘误。）

### 2.4 右缘 / 页内其余 hairline（如实扫到的边）

- 日志列右缘附近 **x≈1595..1605** 有一组竖直浅灰（`#EAEAEC/#E1E1E3/#E2E2E4`），段 y≈1108–1253、各 ~140px
  —— 这更像日志区某局部带（或右侧内物件边缘 AA），**非全列分隔**，不采为全局分隔基准。
- 日志列右极缘 **x≈1797–1798**：`#E4E4E5` 连续 ~500px（y≈594–1096）：是**右日志列的最右侧 border 痕迹**
  （内缩 1px 的浅描边），非全宽结构线（在此之上 log 到右边即可）。
- 页脚/底部区（§4）在 y≈1254 处有 #8C8C8C 文字行，非画线分隔（是状态文本）。

### 2.5 bridge 中其它真·画线点（本次未逐一对、供参照）

bridge 里还有双像素内容线：分隔符主题色是 `StyleColorEntry{ImGuiCol_Separator,#E6E6E6}`(:2119)；
`Section()`(:435)、grid(1294)、sidebar(:1399/1432)皆调 `ImGui::Separator()` 吃到那色。control-buttons doc

## 3. 容器 / 卡片 / 面板 —— 圆角几何实测

### 3.1 左参数列卡片的"圆角 & 边框"真相（与 input/icon doc 一致：无大圆角）

对 x8..400 内组合下拉与其相邻"卡片"做的多采样（锚点综合自 input-select doc §1.2）：

| 量 | 实测 | 出处 |
|---|---|---|
| combo 框边框顶边色 | `#D5D5D5`（顶 5 点全同） | input-select §1.2 |
| combo 圆角 | 可视极小 ~2px AA；约 0–1px（"≈7F round →0-1"） | input-select §1.2 |
| frame 内填 | `#FFFFFF`/`#FEFEFE`（中心白） | input-select §1.2 |
| 卡片底色 / 左列 | `#FBFCFD`（窗口浅蓝白）为主，卡片贴更白 `#FEFEFE` | style doc 共同 |
| **整列卡片外框圆角** | 折角仅 D5 抗锯齿 2px，**无独立大圆角面板/无 drop shadow** | 本文件 + 列扫 |

### 3.2 右大日志"容器"

右日志底纯白 `#FEFEFE/#FFFFFF`，无可见外框 except 最右 x1797 #E4E4E5 极浅 1px 描边（§2.4）。
bridge 的"接收日志大面板"用的是 `Panel("##receive"...)` 白底（:850），无边框、无圆角偏好——对齐。

### 3.3 无"圆角实底大卡片 / 有色描边卡面"型容器可采

全幅仅见三种填充差异作为容器信号，**未见任何一个带明显圆角(>3px)或有色描边的卡面**：
- 左列一连串 D5 细框(表)下拉 + 若干 DEDEDE 顶边叠卡 = **"box list 流派"**，靠边框画控件卡；
- 右日志大片纯白（无框）大区，靠选中高亮(蓝)与正文表达内容分区；
- 底部浅灰（#EEEEF0 等局部）小带（见 §4）。

bridge 的「卡片 = `Panel`(BeginChild)」以整块背景色 child + 可选 border 标界，与 1.png 那种
「以一行 #DEDEDE 顶边 + 紧贴沟线分隔、极少外框与圆角」的形态相异：1.png 真容器更偏
"零装饰 + 发丝分隔"。若要对齐参考，**建议维持 rounding=0 与 `border=false` 的整列流，
仅按 §2 画最小 hairline**（bridge `Panel` 缺省底 #EEEEF0；左列底色实偏 #FEFEFE/#FB 白，非 EEF0 灰）。

### 3.4 侧栏/沟槽量化小结

|---|---|---|
| 面板间空沟宽 | ~20px(x403-422)全空 | `gap=6`(:2367)、(bridge 注释 false 去槽) |

## 4. 状态徽章 / 指示灯 / 链接字色

### 4.1 状态徽章实况：**1.png 无在线绿 / 离线 pill / 圆点徽章基准**

icons doc §5 已证此图绿色像素（含饱和≥40且排除非白）**总数为 0**、无 ONLINE/OFFLINE 圆点，
也无独立数字徽章；本文件不再臆测重复，仅补说明并转述于随后的桥对照，判为"D3 无基准可用"。

图内带饱和的"红"像素只两类：
- **COM 连接红圆点**（x≈217–228, y≈83–94, `#D03430`/`#D00000` 族，~10×10）—— 终端式的
  "已连 COM3"连接指示（control-buttons doc §3.3 同采）。
- 日志错误行文字内低饱和红（见 control-buttons 色盘注释）。

也就是说 1.png 的"红标/状态灯"以**连接点形态**挂左上，**不是**页面右侧跟随"在线/离线"文字的圆点徽章。

### 4.2 蓝色链接 / 标题字色划界（本文件实测）

对偏蓝(navy)文字的三条簇用词频取色，得到主色（§5 色源一致）：

| 区(box) | y | x | 主链主色(计数) | 附次浅蓝 |
|---|---|---|---|---|
| 深蓝文字块 A | 623–641 | x66..344 | `#004275`(713) | #1D5785/#3B6E95/反锯齿链 |
| 深蓝文字块 B | 711–727 | x263..344 | `#004275`(254) | #1D5785/#3B6E95 |
| 底部链 "复位…"等 | 1266–1284 | x1697..1778 | `#004275`(332) | #527DA0/#1B5583/#BFCCD8 |

> 三处的**主笔触同为 `#0042xx`（≈palette `#004270`）** → 1.png "标题/强调文字"正统采样 =
> **#004270 族**（bridge `kTextHeading`/`kAccentPress` 已恰用 0x004270，对齐 ✓）。
> A/B 两处即 input/control doc 曾唤作"蓝色正文链接"的同一实体：实际上更偏"深墨蓝正文带副灰说明"，
> 并非网页链接亮蓝。底部那处才是带浅辉光(淡 #BFCCD8)的"链接样"词。
> 因此 bridge 若把「蓝链接」想成亮 #1850xx 那类链接色 -> 宜改深墨蓝 #0042xx + 浅反光辉来贴近。

### 4.3 对照 `Footer`（bridge.cpp:1516 的自查）—— 徽章不适用

bridge `Footer`(:1516) 在页脚自绘一个 **ONLINE/OFFLINE pill**：底部 `AddRectFilled` 浅青/浅杏圆角
(round 3) + `AddCircleFilled` 3px 圆点 + 文字(:1540-1545)。1.png 页脚（y≈1254..1290）经列扫只见
**灰 `#8C8C8C` 文本（RX/TX 计数等）+ 底部最深 `#1B` 字与"复位计数"蓝链（其蓝即 §4.2 #004270族）**，
**没有任何在线/离线的圆角 pill 或圆点模块** → 结论：
**1.png 无页脚 ONLINE/OFFLINE pill 基准**（bridge 现有 pill 是自设计，非从 1.png 采出；若要对齐 1.png
应把"在线状态"表现为**串口连接红点(x217 圆点)或底行灰/蓝文本**，而非右侧浅色 pill）。

## 5. 字体 / 字号 —— 用 #004270/正文行测量

### 5.1 实测"标题"行几何（深蓝正文，from §4.2 主簇 A）

取最密的一处深蓝文字 A（x66..344）：逐行找 `#0042xx` 族命中并整理为连续 band：

| band | 首行 | 末行 | 连号 ink row count |
|---|---|---|---|
| 最深蓝行 | y=623 | y=641 | **623–641 皆≥(deep blue)** 及 AA 过渡 row 624…640 皆连续 => glyph 纵跨约 19px |

=> 一"标题/主语行"的**墨线高 ≈19px**（含顶部最浅 623 → 底 641）。同一类另一条 B run 为 711–727
（纵 17 行偏紧，属 AA 裁截）。**建议把该行想定为 18–20px 高的标题带**；若 bridge 要把这种"深蓝字
行"复刻，body 图 17px 之外另一档 ~18–19px 更贴（bridge `heading font 18.0` :2241 — 靠近这里）。

### 5.2 正文（#1B1B1B 系）字形/行距

1.png 一般正文/日志多反锯齿黑字；Latin 字形体比格参考 input-select doc（参数白色文本栏内，
字形起始 x≈258–261、字形高 ~15px、字号 ~12.5px）。中文/深正文没有统一、可反推的字号元数据，
用下列实测锚点表述（综合 input/control doc）：
- 灰底"配置/值"拉丁字形高 ~15px、字形左起点 x≈258–261 = text 内边距 17–20px。
- 全图正文色基本 `#1B1B1B`（bridge `ImGuiCol_Text=0x1B1B1B` :2111 —— 对齐 ✓）。
- 底状态计数/弱文字为灰 `#8C8C8C`；深蓝强调见 §4.2/§5.1。
- 段/行距感「值-行 47px 重复、控件帧高 ≈46」出自 input doc，本文不再重复实测。

**单独从 1.png 无法稳健解出"13pt/19 行距"这一具体数字集**（字 rasterize 后无标注字号唯一可反推），
这里诚实标注 **1.png 无文本图元字号说明**；能现固的是行 cap 与色面：上图 A 行 19px、拉丁 15px、
正文色 #1B、标题色 #0042(70)。bridge 字号常量 body 17/heading 18/mono+CJK16(:2234/2241/2248/2296) ——
工程是按大号 DPI 面取，1.png 各行在 canvas 高度多对应 16±2px——总体同一档，无需为对齐去改字号，仅把
"强调字 #004270 字样"色与 A 行对正。
