## 2. 扫描脚本说明（如何在 PIL 中精准抠按钮）

本报告全部数值用一次性脚本产出，脚本放 `D:\tmp\1png_scan\`（**不在项目内**），主配方：

1. **横向细扫找行应**：对每一 `y`，统计该行命中 `#F8F8F8⁄#FFFFFF⁄#C3C2C7⁄#D5D5D5…`
   的像素行数（`01_overview.py`），得到整屏"控件横带"的 y-分量（46px 行的 combo、按 y 轴的色带）。
2. **逐行横跑段(run)找矩形边界**：`runs_in_row(y, target, tol)[…]` 只取 `w>阈值` 的连续色段，
   借此得到每个 combo / 大框的**上/下边框直线**的 x 起止与 w（如 combo 顶 `y=108` => `x=241..399`
   `w=158`，见 `05_cross.py` / `13_boxes.py`）。
3. **纵向列扫补左右边框 / 高**：对固定 `x` 扫 `y` 找出连续 D5D5D5 段，判断是竖边还是圆角侧。
4. **对每个疑似控件矩形采样内填 / 边框 / 字真实颜色**：取 (宽中, 高中) 像素与四边，登记到表格
   （`09b_focused.py / 06/07/15 等`）。
5. **语义缩略图目视锚定布局**：把全图压成 90×60 / 180×130 的 NEAREST 缩略，逐字打印"灰度/蓝/红/
   橙"图例（`07_ascii.py / 08_highres.py`），确认每带是按钮、文本框还是选中行。

> 老实说：本截图绝大部分是**文本日志 + 下拉**，真正独立的"按钮控件"很少（见 §3/§7）。许多被
> 当作"按钮"的区域其实是灰色大文本框或选中高亮。下表几乎每格都是**采到的真实像素**，非臆测；
> 无法确定的项在 §7 明确写明。

## 7. 诚实说明：1.png 上没有、找不到项的实测细节

1. **"打开/关闭 大按钮"**：左侧 405px 下 y=295..335 处我扫到的 5 个 `#EFEFEF`「单元」x=57..100,
   x=116..159, x=175..219, x=244..311, x=328..396 —— 这些是**同一行控件**（更可能是下拉/文本），
   不是开关。（渲染判：其中含文本框 + 复选等）。不采为实心扭。
2. **无彩色实心 Primary/Danger**：全图饱和色检查（`sp`），仅 `#005898 877 / #C00000 606 /
   #F8A800 367 / #004070 344 / 红系文字**低饱和**`。877px 蓝绝大多数是**选中高亮行 + logo + 链接**，
   606px 红是**日志错误字 + 状态点**。故没有一款"实心按钮内填蓝/红"。这正对应当前 bridge 把它们
   画成实心会导致视觉与 1.png 明显不同。
3. **复选钮边框**：全图只在 x=13..34、y=306..1007 这段"纵向 22px 宽的灰竖带"命中较多灰，但这实际
   是 1.png 左缘的播放条/滚动区，非复选钮。真正的复选钮（如 HEX/NEWLINE/Loop）未在 1.png 静止帧露出。
4. **Loop / HEX / NEWLINE**：属于 bridge 的 Multi 页签内容，1.png 未呈现 → 说明无法对。
5. **hover / press 态**：1.png 是静态单帧，无这两态 → 光照（色）不能直接采，但取色已列可引用的
   hover 为 `#2E7FC4`/Active `#004270`（由桥推导，理论上 1.png 深蓝 344px 最接近按色）。

其余已如实列出，坐标皆真。
