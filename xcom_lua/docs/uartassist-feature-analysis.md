## 二、下一步功能优先级建议

### 第一梯队（高价值 / 低成本，建议本迭代做）

1. **发送转义字符解析**（#6）
   - 发送框输入 `AT\r\n`、`\x[01 04 00]` 自动展开。纯 Lua 字符串处理，
     放 `xcom_lua/core/` 新增 `escape.lua`（流式解析器可复用 `ansi.lua` 的写法）。
   - 依赖：无。成本：小。

2. **历史发送记录**（#16）
   - 发送框上箭头召回历史 / 侧栏浮层列表一键重发。Lua 环形数组 + config.ini
     持久化即可，不动 C++。
   - 依赖：无。成本：小。

3. **接收分包显示（粘包切分）**（#20）
   - 空闲 ≥N ms 即断行（UartAssist 默认 50ms）。core 侧 `rx_format_block`
     已有 `display_at_line_start` 行状态，只需在 Dispatcher 加一个"距上块
     间隔超时→行边界复位"判断；参数进 config.ini。
   - 依赖：xcom_core 小改。成本：小-中。
   - 注意：判定在 10ms drain 节奏上做，不引入每字节开销。

### 第二梯队（高价值 / 中成本，下一个迭代）

4. **校验计算器 + 自动附加校验位**（#8 + #17）
   - 算法库（Checksum8/LRC/BCC/CRC16-MODBUS/CCITT/XMODEM…）用纯 Lua 实现
     （查表法，256 项表 `inline` 生成），放 `core/checksum.lua`；
     UI 侧栏加"校验"区：选算法→显示计算结果；勾选"自动附加"→发送前拼接。
   - 这直接解锁 Modbus 联调场景，是竞品用户升级动机最强的功能。

5. **快捷指令增强 + 批量发送**（#12 + #13）
   - 现有 Multi 8 槽位基础上：每条加"延迟 ms"字段 + "开始批量"按钮 +
     循环勾选；指令列表 JSON/TOML 导入导出。
   - 依赖：luv 定时器（已有）。成本：中。

### 第三梯队（暂缓，写明理由）

6. **自动应答规则引擎**（#14）——价值高但规则编辑 UI + 匹配引擎工作量大；
   等第一二梯队落地后评估。
7. **数据波形/示波器**（#15）——WARP 每帧 45-60ms，60FPS 折线图不可行；
   若做只能低频采样刷新（1-2 Hz）+ 独立 child 窗口，收益/成本比差。
8. **指令脚本引擎**（#19）——我们有 LuaJIT，未来直接暴露"发送前 Lua 回调"
   比实现一套类 C 小语法更合理（差异化路线）。
9. **文件数据源发送**（#11）、**多会话**（#21）、**双语**（#23）——按需排后。

## 三、布局优化（视觉美学分析）

### 3.1 当前布局像素度量（board_now.png，920×650）

| 区域 | 边界（实测） | 尺寸 | 占比 |
|------|-------------|------|------|
| Header 深色条 | y 0–37 | 920×37 | 5.7% |
| 接收区（主列） | x 0–740, y 37–431 | 740×394 | 46.2% |
| 发送工作区（主列） | x 0–740, y 432–628 | 740×196 | 23.0% |
| Footer 状态条 | y 630–650 | 920×20 | 3.1% |
| 右侧栏 | x 740–920 | 180×593 | 19.8% |

- 接收:发送 ≈ **2:1**，符合串口工具"看 > 发"的信息层级 ✅
- 主列底色 (248,245,241) 与侧栏 (247,243,237) 亮度差 <1%，分区由 1px 边框线（(132,124,111)）完成——**hairline 极简分区，确认为有意设计方向（用户审美决策，保留）**
- 侧栏内控件（BAUD/DATA 下拉）右缘 x=914，左边距 748，控件宽 ~166px 统一 ✅ 对齐纪律好
- 发送区输入框 (756–822 白色) 与按钮间存在 (247,243,237) 大带，y 586–590 有 4px 空隙条纹——轻微松散

### 3.2 与 UartAssist 经典布局对比

UartAssist 主界面 = 左侧参数栏 + 中央大接收区 + 下方发送区，**工具面板（快捷指令/批量/
自动应答/历史/校验器）独立窗口**。我们的单窗双列 + Multi 页签方案更适合小屏，
不需要照搬多窗口，但应吸收两点：

1. **接收区工具条信息密度**：UartAssist 把"分包/时间戳/HEX/滚屏/清屏/保存"集中在
   接收区顶部一行；我们散在侧栏 DISPLAY 区。建议：DISPLAY 组（HEX/Time/Hold/Clear/Save）
   从侧栏**迁移到接收区工具条**，侧栏只留连接参数（Connection + Serial Profile）。
   收益：侧栏可缩到 ~150px，接收区宽度 +30px；操作与结果同区，减少视线跳跃。
2. **状态可见性**：RX/TX 计数在 footer 两端（实测 y 630–650）离接收区远。建议把
   RX/TX 字节数并入接收工具条右侧，footer 只留状态文字。

### 3.3 具体可执行调整清单

| 优先级 | 调整 | 位置 | 理由 |
|--------|------|------|------|
| 高 | DISPLAY 开关组迁移至接收区工具条右端 | 接收区 y≈44 行 | 信息层级：显示控制应贴着显示区 |
| 高 | 侧栏宽度 180→150（layout.toml `sidebar_width`） | x 740→770 | 迁移后侧栏只剩 5 下拉 + DTR/RTS + Open/Close，可收窄 |
| ~~中~~ **不做** | ~~接收/发送分隔带加 4px 对比底色~~ | — | 设计决策记录：1px hairline 边框分区是有意为之的极简风格（WARP 下无阴影，色带反而显脏），维持现状 |
| 中 | 发送区输入框高度 128→104，腾 24px 给"历史/转义提示"行 | y 466–585 | 为第一梯队功能预留 UI 空间 |
| 低 | Footer 高度 20→24，RX/TX 数字用等宽字体右对齐 | y 626–650 | 计数跳动时不抖动 |
| 低 | 空态（WAITING FOR SERIAL DATA）加 3 行"快速上手"提示 | 接收区中央 | 空区占 46% 画布，信息真空 |

### 3.4 实施边界提醒

- 所有新控件遵守 MEMORY.md 绘图规范：固定字面量宽度缓存（字体指针为 key）、
  draw_list 直绘图标、RAII style stack。
- 分包显示（#20）改动 `rx_format_block` 时先读"接收渲染热路径"表的反模式列。
- 校验表（CRC16 256×2 项）放 Lua 侧生成，避免 DLL ABI 变更。

## 四、建议路线图

**迭代 1（核心调试体验）**
1. 转义字符解析（发送）
2. 历史发送（上箭头召回 + 持久化）
3. 接收分包显示（50ms 间隙断行，可配置）
4. 布局：DISPLAY 组迁移 + 侧栏收窄

**迭代 2（协议调试能力）**
5. 校验计算器 + 自动附加校验位（Modbus 优先）
6. 快捷指令增强（快捷键、导入导出）+ 批量发送（顺序+延迟+循环）
7. 接收保存格式选择（数据/日志）

**迭代 3（差异化）**
8. 自动应答（规则用 Lua 脚本表达，而非自造语法）
9. 文件数据源发送
10. 评估波形：若做，独立 child 窗口 + ≤2Hz 刷新
