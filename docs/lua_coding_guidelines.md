1. **强制 `local`** – 所有变量、函数必须用 `local` 声明，禁止污染全局环境。
2. **缓存全局 API** – 将频繁使用的全局函数（如 `math.sin`、`table.concat`）在作用域顶部缓存为局部变量。
3. **二进制 I/O 显式模式** – Windows 文本模式会把 `\n` 译为 `\r\n` 并在读侧反向翻译；串口原始字节、HEX 载荷、文件发送与落盘日志一律 `io.open(path, "rb"/"wb")`，禁止依赖默认文本模式，防止字节流被静默污染。
4. **换行与断帧显式化** – 行结束符只允许显式 `\r\n`/`\n` 常量（`string.gsub` 拼接时注意 `%` 转义）；断帧按长度/空闲超时判定，禁止依赖平台默认换行行为或文本模式翻译。
5. **字符集纪律** – 项目内部字符串统一 UTF-8；GBK/ANSI 等 Windows 代码页转换只在 C 桥层（cp936 等）完成，Lua 侧禁止对 latin1 字节流做码点级处理（`utf8.len`、`#s` 混用），禁止用 `print` 直出非 ASCII 到控制台（受 `chcp` 影响产生乱码）。
6. **JIT 默认开启，选择性覆盖** – 永远不写全局 `jit.off()`；仅在有实证（崩溃/错误行为或性能测量）时对具体函数 `jit.off(fn)` / `jit.off(fn, line)` 做最小作用域覆盖，并在代码处注释写明"为什么必须解释执行"。
7. **保持 JIT 友好** – 热点循环留在纯 Lua、可 trace 的函数内，不与 C 回调重入路径混用；优先算术、位运算、简单循环和数组操作，确保核心代码能被编译为机器码。
8. **数组遍历用数字 `for`** – 优先 `for i = 1, #arr do`，比 `ipairs` 更快且支持 JIT。
9. **字典遍历用 `pairs`** – 但不要在遍历中修改表内容。
10. **循环拼接用 `table.concat`** – 循环内禁止 `..` 逐步拼接（每次 O(n) 重分配并中断 trace），改用表收集后一次性 `concat`。分块 I/O 中禁止每块一回调一同步读：把吞吐预算换算成"单次事件处理器内按预算连续收发 N 块"，压满一次 I/O 窗口，避免微弱间隔导致的事件风暴。
11. **预分配表大小** – 已知长度时直接下标赋值（`t[i] = val`）；循环内避免新建表，复用固定表并清空（`for i=1,n do t[i]=nil end`）。
12. **元表谨慎用** – 将 `__index`/`__newindex` 设为函数时，注意其查找开销，考虑缓存结果。
13. **FFI 缓存类型** – 用 `ffi.cdef` 定义的结构体，缓存其 `ctype` 和字段访问，减少解析成本。
14. **FFI 回调与字符串边界** – `const char*` 参数只在回调期内借用，跨期必须 `ffi.string`/`ffi.copy` 复制；`ffi.cast` 结果的生命周期须明确，禁止缓存指向临时缓冲的指针。
15. **路径与文件锁** – 目录分隔符统一正斜杠（Lua `io`/OS API 均接受）；Windows 文件系统大小写不敏感，路径去重需用小写键；共享冲突与只读属性是常规失败，必须检查返回值。
16. **外部命令最小化** – 尽量避免 `os.execute`/`io.popen`；确需调用时用 `cmd.exe` 兼容的引号规则包裹参数，禁止拼接未净化的用户输入（命令注入）。
17. **I/O 结果必处理** – 所有 `io.open`/`io.write`/`file:close` 与 `os` 调用必须检查 `nil+msg` 并计数或上抛，禁止静默丢弃；错误信息保留 Windows 错误串便于诊断。
18. **缩进 4 空格**，每行不超过 **120 字符**。
19. **命名风格** – 变量/函数用 `snake_case`，模块/类用 `PascalCase`，常量用 `UPPER_CASE`。
20. **注释用 `-- `** – 解释 **为什么**，而非做什么；公共 API 建议用 EmmyLua 格式。
21. **模块模式** – 每个文件 `local M = {}`，最后 `return M`，杜绝全局暴露。
22. **循环首选 `for`** – 避免 `while`（除非逻辑必须），`for` 更利于 JIT 优化。
23. **避免 trace 中断操作** – 热路径内禁止 `debug` 库调用（如 `debug.getinfo`）、复杂字符串模式匹配与嵌套 `string.gmatch`，改用纯算术或简单操作。
24. **内置 `bit` 库** – 使用 `bit.band`、`bit.bor` 等处理位运算，比纯 Lua 实现快得多。
25. **显式类型转换与真值判断** – 用 `tonumber`/`tostring` 显式转换，不依赖自动转换；条件中仅 `false` 和 `nil` 为假，`0` 和 `""` 均为真。
26. **`require` 置于文件顶部**，并将返回的模块赋值给局部变量（如 `local mod = require("mod")`）。
27. **可变参数用 `select`** – 避免 `{...}` 创建表；频繁调用时用 `select('#', ...)` 获取数量，`select(n, ...)` 取第 n 个后的参数。
28. **弱表管理缓存** – 给元表设 `__mode = "k"` 或 `"v"`，避免缓存成为内存泄漏源。
29. **静态检查与格式化** – 集成 `LuaCheck` 并修复所有警告（尤其全局变量与未使用变量）；使用 `LuaFormatter` 统一风格，提交前自动执行。
30. **牢记 1-based 索引** – 标准库（`string.sub`、`table.insert`）均遵循此约定。
31. **luv 多线程与 loop 归属** – luv 每个 `lua_State` 都有自己独立的 `uv_loop_t`；不同线程（state）之间 **不能共享 uv handle**，但每个线程可拥有独立完整的事件循环。跨线程耦合只传不可序列化值/消息代号，不传 uv handle 或 `lua_State`。（luv 官方 README：每个线程从不同 state 加载库、luv 为其生成独立 loop。）
32. **用 luv 的协同式 `fs_*`/句柄做异步 I/O，别主线程裸轮询** – libuv 的文件/网络/管道操作经线程池在 **C 层异步执行，不阻塞主线程的事件循环**；需要同步风格写异步逻辑时才在独立 `lua_State`（如纤程封装）内用阻塞原语。主 UI 线程禁止用阻塞 `os.execute`/同步 io 读大文件阻塞消息泵——交给 `uv` 的句柄/请求完成回调收口。
33. **阻塞式同步读与临时批量缓冲区勿在每帧分配** – 若必须在单线程内顺序、临时读块（发送/接收转换的局部 IO 窗口），优先大/中批次 + 既有大缓冲，而不要在每次小读里新建表/long-str（避免无谓 GC）。能搬运到独立 luv 线程或 `uv` 句柄收口时优先后者（见 31/32）。
34. **协程当前欠采用并说明原因** – 本项目脚本运行于单共享 `lua_State` 的消息循环（Window:run 事件泵），无独立协程/纤程 host；`lua`/`uv` 官方协程调度器需要宿主按 `lua_State`/`uv loop` 建模（见 31），当前 UI 线程模型不提供。新增长期 I/O 若可能，首先评估"后台 uv 句柄 + 事件回调合并到主循环"；确要实现事件循环内无阻塞多路复用，再引入宿主级协程调度器，而非在本 app 内手写状态机式 yield。
